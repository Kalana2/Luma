\section{Presentation Overview}
% ============================================================

\subsection{Opening}
\begin{quote}
\textit{Good morning/afternoon. Today we are presenting \textbf{Luma}, a Smart Home Monitoring and Control System developed for the module SCS 3311 -- Mobile Application Design and Development.}
\end{quote}

\begin{quote}
\textit{Luma allows a user to monitor and control smart home devices such as lights, outlets, irons, switch panels, and cameras. Since we did not use physical IoT hardware for this mini project, we built a separate web-based hardware simulator. The simulator behaves like virtual smart devices and synchronizes with the Android application through Firebase Realtime Database.}
\end{quote}

\subsection{Project Structure}
\begin{quote}
\textit{The project is organized as a monorepo. The \texttt{android/} folder contains the Android mobile application. The \texttt{simulator/} folder contains the React hardware simulator. The \texttt{firebase/} folder contains Cloud Functions and database rules. The \texttt{docs/} folder contains the report, schema documentation, and presentation material.}
\end{quote}

\begin{longtable}{@{}p{3.2cm}p{10.6cm}@{}}
\toprule
\textbf{Folder} & \textbf{Description} \\
\midrule
\endhead
\texttt{android/} & Native Android application built using Kotlin, Jetpack Compose, Firebase Authentication, and Firebase Realtime Database. \\
\texttt{simulator/} & React and Vite web application that simulates smart home hardware and updates Firebase in real time. \\
\texttt{firebase/} & Firebase project configuration, Realtime Database rules, and Node.js Cloud Functions for automation. \\
\texttt{docs/} & Academic documentation, project report, database schema, and presentation script. \\
\bottomrule
\caption{Main project folder structure.}
\label{tab:main-folder-structure}
\end{longtable}

\subsection{Architecture Summary}
\begin{quote}
\textit{The Android app and the React simulator do not communicate directly with each other. Both are independent clients of the same Firebase Realtime Database. Firebase acts as the single source of truth. When the Android app changes a device state, the simulator receives the update through Firebase listeners. Similarly, when the simulator changes a device state, the Android app receives the update through its Firebase listener.}
\end{quote}

\begin{quote}
\textit{Firebase Cloud Functions provide backend automation. For example, the iron auto-shutdown function checks whether an iron has been on for too long and automatically turns it off for safety.}
\end{quote}

\subsection{Android Entry Point and Navigation}
\begin{quote}
\textit{Now I will explain the Android application. The Android application starts from \texttt{MainActivity.kt}. This file is the entry point of the mobile app. It enables edge-to-edge display, applies the \texttt{LumaaTheme}, and calls the \texttt{AppNavigation()} composable.}
\end{quote}

\begin{quote}
\textit{Inside \texttt{AppNavigation()}, the app uses Jetpack Navigation Compose. The main routes are \texttt{welcome}, \texttt{signin}, \texttt{signup}, \texttt{dashboard}, \texttt{floor\_details/\{floorId\}}, and \texttt{camera\_feed/\{deviceId\}}. This navigation flow allows the user to move from the welcome screen to authentication, then to the dashboard, then to floor details and camera monitoring.}
\end{quote}

\section{Firebase Backend Script}
% ============================================================

\subsection{Firebase Configuration}
\begin{quote}
\textit{Firebase is the central backend of Luma. It provides Authentication, Realtime Database, and Cloud Functions. The Android app and simulator both connect to Firebase. Firebase Realtime Database stores users, floors, rooms, devices, alerts, reports, and device history.}
\end{quote}

\subsection{Database Rules}
\textbf{File:} \texttt{firebase/database.rules.json}

\begin{quote}
\textit{The database rules file controls read and write permissions for Firebase Realtime Database. In a Firebase-based system, security rules are important because clients connect directly to the database instead of going through a custom backend API.}
\end{quote}

\subsection{Cloud Function Entry File}
\textbf{File:} \texttt{firebase/functions/src/index.js}

\begin{quote}
\textit{The file \texttt{index.js} exports all Firebase Cloud Functions used in the project. These functions are \texttt{ironAutoShutdown}, \texttt{disconnectionDetector}, \texttt{lightScheduler}, \texttt{reportAggregator}, and \texttt{alertNotifier}.}
\end{quote}

\subsection{Iron Auto-Shutdown Function}
\textbf{File:} \texttt{firebase/functions/src/ironAutoShutdown.js}

\begin{quote}
\textit{The iron auto-shutdown function is a safety automation feature. It runs every minute and checks all devices. If a device is an iron, if its state is ON, and if it has been on longer than its configured maximum duration, the function automatically sets the iron state to OFF. It also clears the \texttt{turnedOnAt} value, updates \texttt{lastSeen}, and creates an alert.}
\end{quote}

\textbf{Corresponding UI section:} Auto Shutdown Timer card in \texttt{DeviceDetailPage.tsx}.

\subsection{Light Scheduler Function}
\textbf{File:} \texttt{firebase/functions/src/lightScheduler.js}

\begin{quote}
\textit{The light scheduler function checks smart light devices every minute. It compares the current time with the saved \texttt{startTime} and \texttt{endTime}. If the current time is inside the schedule, the light is turned ON. Otherwise, it is turned OFF.}
\end{quote}

\textbf{Corresponding UI section:} Auto Schedule card for light devices in \texttt{DeviceDetailPage.tsx}.

\subsection{Disconnection Detector Function}
\textbf{File:} \texttt{firebase/functions/src/disconnectionDetector.js}

\begin{quote}
\textit{The disconnection detector checks whether devices have stopped updating their \texttt{lastSeen} timestamp. If a device has not been seen for more than the threshold, the function marks it as \texttt{DISCONNECTED} and creates an alert.}
\end{quote}

\textbf{Corresponding UI sections:} device status chips, dashboard error count, and logs/alerts page.

\subsection{Report Aggregator Function}
\textbf{File:} \texttt{firebase/functions/src/reportAggregator.js}

\begin{quote}
\textit{The report aggregator runs when a device changes from ON to OFF. It calculates how long the device was on, estimates energy consumption using nominal wattage values, writes a history entry, and updates the report data.}
\end{quote}

\textbf{Corresponding UI section:} device history and reports tabs in \texttt{LogsPage.tsx}.

\subsection{Alert Notifier Function}
\textbf{File:} \texttt{firebase/functions/src/alertNotifier.js}

\begin{quote}
\textit{The alert notifier runs when a new alert is created under the \texttt{/alerts} node. It reads the related device name and logs the alert type, message, device, and timestamp. This supports safety and monitoring events in the system.}
\end{quote}
